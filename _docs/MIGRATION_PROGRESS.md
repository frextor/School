# Suivi de migration CodeIgniter → Laravel

Source : `D:\laragon\www\amos_schooltech\intranet\application`
Cible : `D:\laragon\www\school`
Base de données : `miracle` (locale, structure copiée depuis la prod, sans données) — préfixe legacy `amos_`.

**Nom du projet : Scoleo.** `APP_NAME`/`SCHOOL_NAME` renommés (n'utilisaient déjà que des valeurs génériques, pas "AMOS"), `APP_KEY` régénérée (jamais réutiliser la clé de chiffrement d'un autre projet). Landing page publique ajoutée à `/` (`LandingController` + `resources/views/landing.blade.php`), qui remplace la redirection brute vers `/admin` et présente les 4 espaces (admin/élève/intervenant/entreprise) + l'auto-inscription intervenant.

**Revue transversale de bout en bout (après renommage + nouvelle `APP_KEY`)** : landing (200) → login admin → dashboard admin (session ok, nom affiché) → logout ; login élève → accueil élève (200, topbar + nom affiché) ; login entreprise → accueil entreprise (200, topbar + nom affiché). Tout fonctionne après régénération de la clé de session. Seul point relevé : l'affichage `Espace élève` semblait corrompu dans un test via terminal `LC_ALL=C` — vérifié aux octets, c'est bien de l'UTF-8 valide (`é`/`è`), faux positif de l'outil de test, pas un bug applicatif.

## Méthodologie
1. Modèles Eloquent générés automatiquement pour toutes les tables (squelette : table, PK, fillable, casts basiques).
2. Modules migrés un par un : controller CI → Controller Laravel + routes + vues Blade, en relisant le code source CI à chaque fois (pas de génération automatique de logique métier).
3. Chaque module fermé est coché ci-dessous avec la date et un résumé de ce qui est couvert / pas couvert.

## Fondations
- **195 modèles Eloquent générés automatiquement** depuis le schéma (`php artisan legacy:generate-models`), un par table `amos_*`. À affiner (relations, casts, accessors) au fil de la migration de chaque module.
- **Authentification back-office** (`Admin.php` / `Login_model.php` CI) : portée intégralement.
  - Modèle `App\Models\Admin` (Authenticatable, table `amos_admins`), mot de passe legacy en `md5()` sans salt géré via `Admin::checkPassword()`.
  - Guard Laravel dédié `admin` (`config/auth.php`), guard par défaut de l'app.
  - `AdminAuthController` (login/logout), vue `auth/login`, dashboard `admin/dashboard`.
  - Toutes les routes métier sont protégées par `middleware('auth:admin')`.
  - Testé de bout en bout (login réussi/échoué, redirection, accès protégé).

## Décisions de portage notables
- Les vues legacy pilotées par DataTables server-side (`draw`/`recordsTotal`/`recordsFiltered`) sont remplacées par la pagination Eloquent standard (`paginate()`), le contrat JSON n'ayant pas vocation à être repris tel quel côté nouveau front.
- `url_title(convert_accented_characters())` → `Illuminate\Support\Str::slug()`.
- Les suppressions "métier" du legacy qui ne suppriment pas réellement (ex. élèves) sont reproduites par un flag plutôt qu'un `DELETE` réel, sauf quand le legacy fait lui-même un vrai `DELETE` (ex. rôles).
